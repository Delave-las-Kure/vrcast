# VRCast Studio

Управление собственным стриминг-сервером VRCast: библиотека медиа, подготовка видео,
надёжная заливка, наблюдение за зрителями и ручное ограничение качества тем, у кого слабый канал.

**Состояние: веха A, Фаза 1 (каркас).** Приложение ещё не делает ничего полезного.
Пока веха A не сдана, вся работа выполняется прежним способом — скриптами `.claude/skills/vrcast-*`
в родительском каталоге. Они не изменяются и остаются рабочим запасным путём до конца разработки.

## Требования

| | |
|---|---|
| Node | 20+ |
| Rust | 1.83+ |
| Windows | MSVC C++ toolset (нагрузка «Разработка классических приложений на C++» в Visual Studio) |
| Linux | `libwebkit2gtk-4.1-dev`, `libappindicator3-dev`, `librsvg2-dev`, `patchelf` |

macOS не поддерживается: отложена намеренно, см. `specs/001-vrcast-studio/spec.md`, раздел «Вне объёма».

## Разработка

```bash
npm install
npm run tauri dev        # запуск
npm run tauri build      # установщик под текущую ОС

npm run lint             # стиль интерфейса
npm run typecheck        # типы
npm run test             # тесты интерфейса
cargo test --manifest-path src-tauri/Cargo.toml   # тесты ядра
```

## Проверки перед сдачей фазы

```bash
npm run check:isolation      # ничего вне vrcast-studio/ не изменено (принцип VII)
npm run check:no-hardcoded   # в коде нет захардкоженного сервера (FR-004)
```

Эталон изоляции записывается один раз: `bash scripts/check-isolation.sh baseline`.

## Устройство

| Часть | Где | Отвечает за |
|---|---|---|
| Ядро | `src-tauri/src/` | всю логику и всё общение с внешним миром: сервер, файлы, задачи |
| Интерфейс | `src/` | только показ; про SSH и FFmpeg не знает ничего |
| Серверная часть | `src-tauri/resources/server/` | версионируемый набор настроек, разворачиваемый на VPS (Фаза 7) |

Договор между ядром и интерфейсом зафиксирован в `specs/001-vrcast-studio/contracts/ipc-commands.md`
и проверяется тестами. Договор с сервером — в `contracts/server-contract.md`.
