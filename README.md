# VRCast Studio

Настольное приложение для управления сервером, с которого раздаются видео в VRChat:
библиотека, подготовка файлов, заливка, зрители, ограничения качества.

Работает с **любым** VPS: адрес, домен и пути берутся из профиля, который заводит
пользователь. Своего сервера у приложения нет и быть не может — это проверяется
отдельным стражем в сборке.

> **Состояние: веха D.** Работают все разделы: серверы, библиотека, подготовка,
> заливка, наборы качеств, зрители, ограничения, диагностика, задачи и оформление.
>
> Заливка идёт с продолжением после обрыва и **переживает закрытие приложения**:
> при следующем запуске задача ждёт вашего решения и продолжается с достигнутого
> места.
>
> **Сервер разворачивается из приложения** — из пустого VPS, без единой команды в
> консоли. Прогнано на настоящей машине: домен отвечает по HTTPS с живым
> сертификатом.
>
> Осталась веха «Поставка»: установщики, подпись, обновление.

## Чем это отличается от скриптов в `.claude/skills/`

Скиллы `vrcast-*` в корне проекта — прежний способ работы, и он **продолжает
работать**. Приложение их не заменяет и не трогает: это отдельный каталог со своим
репозиторием, а неприкосновенность скриптов проверяется при сдаче каждой фазы.

Пользуйтесь тем, что уместнее:

| | Скиллы | Приложение |
|---|---|---|
| Разовое действие по знакомой схеме | быстрее | — |
| Увидеть библиотеку целиком, с параметрами файлов | — | да |
| Понять, куда ушло место на диске | — | да |
| Заливка с продолжением после обрыва | — | да |
| Заливка переживает закрытие приложения | — | да |
| Очередь задач с перестановкой | — | да |
| Подготовка файла (пересжатие) | быстрее | да |
| Обязательная проверка воспроизведения | — | да |
| Работа без знания командной строки | — | да |
| Несколько серверов | — | да |
| Кто смотрит прямо сейчас | — | да |
| Набор качеств по замеру, а не по формуле | — | да |
| Ограничить качество одному зрителю | вручную, правкой конфига | да |
| Развернуть сервер из пустого VPS | вручную, по шагам | да, без консоли |
| Довести прерванное развёртывание | вручную, разбираясь, где встало | да, повторным запуском |

| Снимок состояния с оценками | да | да |
| Разбор журнала и причины подвисаний | да | да, с числами под выводом |
| Пики битрейта файла | да | да, с хронометражем |

Если вы уже работаете скриптами и у вас есть `server.env`, приложение предложит
перенести из него настройки при создании первого профиля. Файл при этом **только
читается** и не изменяется.

## Сборка

Нужны Rust 1.83+, Node 20+ и системные зависимости Tauri для вашей ОС. Целевые
системы — Windows 10/11 и Linux; **macOS не собирается** и не заявляется.

```bash
cd vrcast-studio
npm install
npm run ffmpeg         # положить вложенный FFmpeg (около 280 МБ, качается один раз)

npm run tauri dev      # запуск для разработки
npm run tauri build    # установщик под текущую ОС
```

`npm run ffmpeg` скачивает закреплённую сборку FFmpeg, **сверяет её слепок** и кладёт
рядом с ядром. Сборка установщика делает это сама; для разработки и тестов её нужно
позвать руками один раз. Что именно берётся и почему — в `scripts/ffmpeg.json`;
там же обязательства открытой лицензии. У пользователя приложение не скачивает
ничего (FR-112).

## Проверки

Перед отправкой — одной командой всё, что проверяет непрерывная интеграция:

```bash
npm run check:all          # формат, clippy, тесты, лицензии, стражи
npm run check:all -- --full  # плюс сборка под Linux и одноразовый сервер
```

Она существует не для удобства: проверки разбросаны по четырём командам и двум
языкам, и обойти их все по памяти получается не всегда. Каждый пропущенный круг
стоит десяти минут ожидания CI и лишнего коммита в истории.

По отдельности:

```bash
npm run typecheck && npm run lint && npm run test   # интерфейс
cargo test --manifest-path src-tauri/Cargo.toml     # ядро
```

Проверки против настоящего OpenSSH поднимают одноразовый контейнер и удаляют его
за собой. Нужен запущенный Docker и `ssh-keygen` (ключ для контейнера создаётся
на месте и в репозиторий не попадает):

```bash
cargo test --manifest-path src-tauri/Cargo.toml \
  --features integration --test integration -- --test-threads=1
```

Однопоточность обязательна: каждая проверка поднимает свой контейнер.

### Стражи

```bash
# В приложении не должно быть ни одного захардкоженного сервера (FR-004).
FORBID_IP=… FORBID_DOMAIN=… bash scripts/check-no-hardcoded-server.sh

# Разработка приложения не имеет права трогать скиллы и настройки прежнего порядка.
bash scripts/check-isolation.sh check

# Лицензии зависимостей совместимы с GPL, известные уязвимости разобраны поимённо.
cargo deny --manifest-path src-tauri/Cargo.toml check licenses advisories

# Перечень чужих работ (THIRD-PARTY.md) отвечает дереву зависимостей.
# Собрать заново: npm run third-party
npm run check:third-party
```

Есть ещё две проверки, требующие настоящего сервера, — они не входят в обычный
набор и запускаются вручную:

```bash
# Сценарий приёмки вехи A: только чтение, сервер не изменяется.
cargo test --manifest-path src-tauri/Cargo.toml --features integration \
  --test integration -- --ignored --nocapture the_live_server_read_only

# Поиск секретов в подробном журнале настоящего подключения (SC-011).
bash scripts/check-no-secrets-in-logs.sh

# То же, но против одноразового контейнера: заливка, зрители, лесенка, ограничения,
# развёртывание и диагностика. Настоящий сервер для этого не нужен и не годится.
bash scripts/check-no-secrets-in-logs.sh container
```

## Заливка

Раздел «Заливка»: выбрать готовый файл, сказать, под каким именем его увидят
зрители и к какому медиа он относится, при желании ограничить скорость — и всё,
дальше можно закрыть экран. Ход виден в разделе «Задачи».

Что важно знать заранее, потому что приложение об этом молчать не станет:

- **Все проверки идут до начала передачи.** Мало места на сервере — отказ сразу,
  а не через час на середине. Идёт просмотр — предупреждение: заливка вымоет
  из памяти сервера то, что смотрят, и у зрителей подвиснет. Имя занято — тоже
  предупреждение, с оговоркой про кеш CDN, если он задан.
- **Нехватку места подтверждением не снять.** Остальные предупреждения снимаются
  кнопкой «всё равно залить» — места от согласия не появится.
- **Обрыв связи не считается неудачей.** Передача продолжается с достигнутого места,
  переподключаясь до восьми раз с нарастающей паузой.
- **Закрытие приложения не теряет работу.** При следующем запуске задача ждёт
  вашего решения — продолжить или снять — и продолжается с того же места. Позиция
  берётся из размера недокачанного файла **на сервере**, а не из локальной записи:
  локальная могла устареть.
- **Недокачанный файл не виден зрителям ни в один момент.** Он собирается вне
  каталога раздачи и попадает туда одним переименованием, уже после сверки
  контрольных сумм. Не сошлись — файл в раздачу не идёт, временное убирается.
- **Порядок очереди можно менять.** Уже начатую задачу перестановка не трогает:
  прервать её значило бы выбросить сделанное.

## Подготовка файла

Раздел «Подготовка»: выбрать исходник, увидеть, что в нём на самом деле, выбрать
звуковую дорожку — и подготовить. Приложение приводит файл к формату, который
играет плеер VRChat: MP4, H.264, звук AAC стерео, служебные данные в начале файла.

Что стоит знать заранее:

- **Совместимое переносится без пересжатия.** Это минуты вместо часов и ноль
  потерь. Экран говорит прямо, что именно будет сделано и почему, — до того,
  как вы согласитесь.
- **Заданный битрейт означает пересжатие**, даже если файл и так подходит: иначе
  ваше требование осталось бы невыполненным, а вы бы об этом не узнали.
- **HEVC пересжимается всегда**, хотя формально уже сжат. В Windows нет системного
  декодера HEVC, и у части зрителей такое видео не играет вовсе — проверено боем.
- **Об аппаратном ускорении не молчат.** Если его нет, кодировать будет процессор:
  качество от этого не пострадает, а времени уйдёт в разы больше. Знать об этом
  надо заранее, иначе долгая работа выглядит зависанием.
- **Готовый файл обязательно проверяется на воспроизведение** (полный декод).
  Не прошедший проверку к заливке не предлагается: сломанный энкод открывается,
  показывает верную длительность и разваливается там, где на него смотрят.
- **Приостановка действительно останавливает работу**, а не только меняет надпись.
  Кодировщик замораживается, а не убивается: сделанное не теряется.

## Кто смотрит прямо сейчас

Раздел «Зрители»: список тех, кто в эту минуту качает с вашего сервера — адрес,
откуда, что смотрит, с какой скоростью и как долго. Список обновляется сам, пока
экран открыт: спрашивать заново о том, что меняется каждые несколько секунд, значит
удваивать нагрузку на сервер ни за чем.

Что стоит знать:

- **Источников два, и оба нужны.** Журнал обращений говорит, что смотрят, но
  запись в нём появляется только когда просмотр закончился. Таблица соединений
  сервера говорит, кто тянет прямо сейчас. Ни один из двух в одиночку не отвечает
  на вопрос «кто смотрит».
- **Место зрителя определяется на вашем компьютере.** Страна, город и провайдер —
  по таблицам, которые приложение скачивает само; ни один адрес наружу не уходит.
- **«Не хватает связи» — это замер, а не догадка.** Скорость считается по тому,
  сколько байт сервер подтвердил доставленными, и сравнивается с тем, сколько
  требует ступень, которую зритель получает.
- **Слежка держит два канала соединения** из восьми, пока экран открыт. Закрыли —
  отпустила.

## Набор качеств

Раздел «Набор качеств»: несколько вариантов одного фильма, между которыми плеер
зрителя переключается сам.

- **Ступени выбираются по замеру, а не по формуле.** Приложение кодирует три
  коротких куска — лёгкий, средний и тяжёлый — в нескольких качествах и смотрит,
  что из этого выходит на самом деле. Формула материала не знает: на мультфильме
  просит втрое больше нужного, на плотном действии занижает.
- **Сколько это займёт, говорится до запуска** — и говорится, на чьей машине
  снята оценка. После первой же вашей посчитанной точки оценка уточняется сама.
- **Замер переживает отмену.** Каждая точка записывается сразу; повторный запуск
  досчитывает недостающие, а не начинает заново.
- **Замер соседней серии можно одолжить** — источник тот же. Одолженный помечен:
  ступень на чужом замере не замеренная ступень.
- **Ступень, поправленная руками, перестаёт быть замеренной** — никто не смотрел,
  чего она стоит на новом значении. Собрать набор из незамеренных ступеней
  приложение отказывается.
- **Отрезки рождаются на сервере**, а не гоняются по сети сотнями мелких файлов.
  Работа отцеплена от соединения и переживает обрыв.
- **Успехом считается только полная отдача.** Проверяется каждый вариант, а не
  первый: набор, где верхняя ступень играет, а нижняя нет, хуже, чем никакого —
  зритель, ради которого его строили, остаётся ни с чем.

## Ограничение качества

Тормозящему зрителю можно выдать только посильные ступени, не трогая остальных.
Плеер берёт лучшее из показанного и уговорам не поддаётся — значит непосильные
просто не показываются.

- **Видеоданные не копируются.** Делается только урезанное описание набора; место
  под раздачей растёт меньше чем на процент.
- **Предупреждения приходят до применения и требуют согласия.** Ограничение
  ставится на адрес, а адрес — не человек: за ним может быть целый дом, и он
  может смениться.
- **Приложение правит один свой файл**, а основной конфиг раздачи — никогда.
  Ошибка стоит правила, а не всей раздачи.
- **Любая неудача откатывается.** Прежний файл возвращается, раздача
  перезагружается и проверяется — идущий просмотр не прерывается.
- **Список ограничений читается с сервера**, а не из записи в приложении: запись
  устаревает в тот час, когда сервер правят руками.

## Развёртывание сервера

Из пустого VPS в раздающий сервер — из приложения, без консоли. Нужны только адрес,
пароль или ключ и домен, ведущий на эту машину.

- **Ничего не начинается, пока вы не увидели список изменений и не согласились.**
  Список поимённый: какой пользователь заводится, какие каталоги, какие порты
  открываются, какие настройки ядра меняются. Это ваша машина, и вы вправе знать.
- **Домен проверяется до начала**, обходом от корневых серверов DNS, а не через
  чужой распознаватель — тот кеширует «нет такого домена» на десятки минут после
  того, как вы всё исправили. Отказ говорит, **что пойти и завести** у регистратора:
  тип записи, точное имя, точное значение и куда она ведёт сейчас.
- **Шаг считается сделанным, когда так говорит его проверка**, а не когда его
  применение вернулось без ошибки. После применения вопрос задаётся заново.
- **Прерванное развёртывание доводится повторным запуском** — с любого места, включая
  самое неприятное: вход по паролю уже выключен, а работа не закончена.
- **Чужой сервер узнаётся и не переписывается.** Как и сервер новее этого приложения:
  его можно посмотреть, но не изменить.
- **Вход по паролю выключается, и это доказывается попыткой войти**, а не строкой в
  файле. Строка в файле шесть месяцев прикрывала незакрытую дверь на боевом сервере.

Что ставится на вашу машину и на каких условиях — в [THIRD-PARTY.md](THIRD-PARTY.md),
раздел «Серверная часть». Состав заморожен версией 1 и сверяется с кодом при каждом
прогоне проверок.

## Диагностика

Отвечает на «почему подвисает», и отвечает **числами**, а не готовой фразой: вывод
бывает неверен, и его должно быть чем оспорить.

- **Снимок сервера** с оценкой по каждому показателю: раздача, отдача по HTTPS,
  защита, память и кеш раздачи, диск, сетевые настройки. «Не удалось выяснить» —
  отдельный ответ, а не «норма».
- **Разбор журнала раздачи** за промежуток: коды ответов, зрители, что просили,
  ошибки. Журнал читается с конца порциями — целиком он весит до 250 МБ.
- **Почему у зрителя встаёт картинка.** Порядок разбора взят из разбора настоящего
  случая: спит ли сервер → канал зрителя → и только потом сам файл. Скорость зрителя
  считается по стенным часам, а не по длительности запросов: это разные числа, и его
  канал — первое из них.
- **Пики битрейта файла** с хронометражем: где именно тяжело. Файл читается на вашей
  машине, сервер не трогается — спросить можно и до заливки.

## Оформление

- **Тема** светлая, тёмная или как в системе; системную приложение подхватывает на
  ходу, а не при следующем запуске.
- **Язык** русский или английский, каждый назван на себе самом.
- **Маскот** отражает то же, что и список задач: работу, успех, ошибку, беду у
  зрителя. Выключённый — **не загружается вовсе**, а не просто прячется.
- **Движение** выключается настройкой, а системное «уменьшить движение» перевешивает:
  выключенное в системе приложение обратно не включает.

Все настройки лежат в одном месте — в базе ядра. Второе хранилище того же выбора
расходится молча, и починить это пользователь не может, потому что второго места
не видит.

## Как устроено

```
src/               интерфейс: React + TypeScript
  shared/i18n/     словари: по одному на язык, плюс подстановка значений
src-tauri/src/
  domain/          правила, не зависящие ни от сервера, ни от файловой системы
  domain/wording/  что ядро умеет сказать — кодами, а не фразами
  error.rs         ошибка как объект: код, уточнения, техническая подробность
  server/          как узнать то, что знает сервер: опись, каталог, диск, заголовки MP4
  server/deploy/   пятнадцать шагов развёртывания: у каждого проверка, применение и опись изменений
  server/health.rs снимок состояния одной командой
  net/dns.rs       обход от корневых серверов: проверка доменной записи без посредников
  ssh/             одно соединение на сервер, каналы внутри него
  tasks/           очередь задач, полосы по ресурсам, гарантированное завершение процессов
  store/           локальная база, кеш библиотеки, секреты
  commands/        единственная граница между интерфейсом и ядром
```

Черта между `domain` и `server` проходит по одному признаку: там — **что известно**,
здесь — **как это узнать**. Всё, что можно проверить без сервера, живёт в `domain`
и проверяется без него.

Договор слоя команд описан в
[`specs/001-vrcast-studio/contracts/ipc-commands.md`](../specs/001-vrcast-studio/contracts/ipc-commands.md);
что приложение вправе трогать на сервере — в
[`server-contract.md`](../specs/001-vrcast-studio/contracts/server-contract.md).
Перечни кодов ошибок, уточнений и событий сверяются между Rust и TypeScript
автоматически, в обе стороны: расхождение роняет сборку.

## Язык интерфейса

Русский и английский, переключаются в левом столбце. Выбор запоминается; при первом
запуске берётся из настроек системы.

Ядро не сочиняет фраз ни на одном языке. Оно называет случай кодом и передаёт значения
для подстановки — сколько байт не хватило, какой файл, сколько соединений открыто.
Формулировки живут в `src/shared/i18n/`, по словарю на язык. Отсюда два следствия:

- одна и та же беда объясняется одинаково на всех экранах — формулировка одна;
- ошибка, записанная в задачу неделю назад, объяснится на том языке, который выбран
  сегодня: в базе лежит код, а не предложение.

Числа тоже уходят числами: «22,0 ГБ» и "22.0 GB" — одно значение, записанное двумя
языками, и выбирает запись интерфейс.

Полнота словарей проверяется, а не оставлена на внимательность: английский словарь
типизирован русским, поэтому пропущенный ключ роняет сборку, а отдельная проверка
в ядре читает оба файла и требует формулировку для каждого кода.

## Что приложение делает с вашими доступами

Пароли, парольные фразы и ключи хранятся в **хранилище учётных данных операционной
системы** — Credential Manager на Windows, Secret Service на Linux. В файлах
приложения и в его базе лежит только ссылка на запись; поля под сам секрет там нет.

Секрет пересекает границу между интерфейсом и ядром ровно один раз — когда вы его
вводите. Обратно он не возвращается никогда, ни одной командой; это проверяется
поиском по ответу каждой команды.

Всё, что уходит в журнал, проходит через вырезание секретов. Приватный ключ
узнаётся по виду, даже если он попал в вывод мимо хранилища.

Приложение **не подключится к серверу, отпечаток которого вы не подтвердили**.
До подтверждения ни пароль, ни ключ серверу не отправляются — так подменённый
сервер не получит ваши учётные данные, даже если сумеет притвориться нужным адресом.
